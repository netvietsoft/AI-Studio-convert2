# TASK_185 R1 — bounded nonexport FDE candidate research

This batch processed all **128/128** exact VA-sorted candidates in the Chairman/CEO-pinned target manifest for original `libPVGColorFunctions.so`. Every candidate range is an `.eh_frame` FDE start absent from 81 defined nonzero-size `.dynsym` function export VAs. This is a bounded candidate batch, not an internal-function census: the manifest leaves 544 other nonexport FDE candidates unselected, and FDE starts alone do not prove exact function boundaries.

All 128 original body ranges were independently matched to ELF FDE start/range, PT_LOAD file offset and SHA-256. Source Capstone decoded 10,253/10,253 AArch64 instruction slots. The prior TASK_168 analyzed Ghidra project was copied into private TASK_185 scratch with 9/9 historical/copy file hashes matching before and after the run; no fresh import occurred. Four sequential Ghidra processes ran with `-max-cpu 1`, 1 GiB configured heap and <=20-minute process caps. Raw command/output/logs are retained.

Ghidra memory matched the original body SHA in **128/128** rows. Listing instructions cover **10,253/10,253** slots and p-code is present for **10,201/10,253** slots. C-like text exists for **128/128** Ghidra functions. Only **90/128** Ghidra function bodies exactly equal the pinned FDE ranges; the other **38/128** are classified `GHIDRA_BODY_DOES_NOT_COVER_FDE_RANGE`, so their C-like text is boundary-limited and cannot be claimed as full-FDE recovery. No function metadata was created by this script; the copied analyzed project already had entries at all 128 starts. Detailed per-candidate ranges, failures, p-code counts, source/copy hashes and C-like hashes are in `candidate_index.json` and raw chunk NDJSON.

Independent verifier rehashed every original body and compared the Ghidra memory digest for every row. It also sampled 16/128 candidates (12.5%) spread across the full VA-sorted batch and checked 40 first/middle/last instruction words against original bytes, Capstone source assembly and Ghidra listing addresses. Evidence is in `independent_verification.json`.

Disposition: **PARTIAL_STATIC_FDE_BOUNDARY** for full-FDE C-like recovery. Source bytes, instruction coverage, p-code presence and C-like decompiler text are separate evidence levels. No dynamic execution, pixel/behavioral equivalence, product Phase PASS, V4 implementation, or all-45-SO completion is claimed. Scope and research package are complete for these exact 128 rows; remaining boundary ambiguity and 544 unselected candidates require separate CEO decisions/tasks. `PROJECT_ERROR.md`/`ACQUIREMENTS.md` were consulted; this task did not have write scope to modify them. No commit or push was made pending CEO review.

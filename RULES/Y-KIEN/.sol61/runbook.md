# SOl 6.1 — Local report/code reviewer

Purpose: scan local tasks and AGY reports, queue changed evidence for independent review, and publish human/agent-authored numbered opinions. This tool never runs AGY generators or changes task/report/product source or AGY completion state.

From `F:\CONVERT\com.mt.mtxx.mtxx\CONVERT2`:

```powershell
python -X utf8 -B 'RULES\Y-KIEN\.sol61\monitor.py' scan
python -X utf8 -B 'RULES\Y-KIEN\.sol61\monitor.py' status
python -X utf8 -B 'RULES\Y-KIEN\.sol61\monitor.py' publish --review-id <ready_review_id> --body-file 'RULES\Y-KIEN\.sol61\review-body.md' --verdict NEEDS_FIX
python -X utf8 -B 'RULES\Y-KIEN\.sol61\test_monitor.py' -v
```

Repeat `--review-id` to publish one opinion covering several explicitly reviewed items. Do not select unrelated pending items. Use NEEDS_FIX, OBSERVED, RESEARCH_PENDING or AWAITING_CEO_AUDIT as the review disposition; PASS and ACCEPTED are forbidden. No claim that a task is complete follows from a report directory, receipt, PID, checksum or reviewer-tool test result.

The state file `RULES\Y-KIEN\.sol61-audit-state.json` holds the scheduler ID, observed fingerprints, pending revisions and published opinion bindings. Preserve it across restarts. Historical tasks without reports are initially observed without calling them accepted. Exact ACTIVE parsing, supersession and MD/DOCX content agreement determine intake eligibility. Task intake and report review are separate units for the same task identity.

Every scan reads the canonical standard and checks its SHA. A valid reviewer lease with more than five minutes remaining is read without rewriting the registry. Renewal uses the common `.ai/locks.registry.guard`, the reviewer guard `.ai/locks.sol61.guard`, and byte comparison before replacement; a detected concurrent registry change stops renewal. Other lease writers must honor the common guard for full serialization: arbitrary writers that bypass it cannot be fully protected by a private reviewer. An OS lock at `.sol61-audit.lock` protects state/publication. Product/P0 sources are hashed only. Code/evidence changes can invalidate a prior opinion even when a report is unchanged.

Without a valid comprehensive FREEZE.sha256, a report must have identical task/report/source fingerprints over at least two scans 60 seconds apart. Partial-file markers block readiness. Ready means eligible for an independent audit, not technically correct or accepted. Publishing rechecks the fingerprint and lease, journals the operation and atomically creates `SOl 6.1 _NNN.md` without replacing an existing file. Recovery completes a journal whose final opinion bytes match; evidence conflicts stop publication.

Heartbeat: Paseo, cron `* * * * *`, timezone `Asia/Bangkok`, current agent, no expiry/max-runs limit. Stored ID: `baf57b95`. This Paseo version's generic schedule list/inspect/log API excludes agent heartbeats; a “not found” there does not establish deletion. The owned native record is `%USERPROFILE%\.paseo\schedules\baf57b95.json`; read only its cadence/status/run metadata, not global configuration or credentials. Use `paseo heartbeat update` or the heartbeat-specific delete tool to manage this exact heartbeat. Do not register a duplicate.

The daemon rejects a heartbeat while the target agent already has an active turn. Recorded busy ticks are scheduling attempts, not successful deliveries; the next minute can start a turn when the agent is idle. At registration, delivery success remained unverified because this implementation turn was still active. Subsequent scans record native heartbeat health and verify it after two actual succeeded runs. Runtime availability controls delivery. The agent stays quiet when no newly reviewable revision exists.

For each ready revision the reviewer must read the corresponding task and report, inspect cited source/raw evidence, reproduce safe necessary checks and write an actionable review. Missing evidence remains explicit. Reports in progress stay pending until stable; no automatic opinion body or automatic technical verdict is generated by the monitor.
